apsw-gridwright playground

Everything below runs the built package from dist/ through the headless core, with no React. Switch the data source and watch the badges: each facet of the query is resolved either by the server or by the in-memory pipeline, and nothing above that seam changes.

Also here: the React component and the page where every option is switchable.

The tree, with no framework

The nested set, the controller and the flattening stage are all core, so this is the same tree the React component draws, rendered here by forty lines of innerHTML in this page. Click a name to expand it, right-click a row for its actions. What React adds is the markup, not the hierarchy.
Editing in place is not wired up here: this panel is about the hierarchy, and the grid below has the editors. Click a row for its menu, or right-click it.
It is stored on the server. Every change is posted to /api/files, which keeps the tree as an adjacency list, one row per node naming its parent and its position. Add or delete something and reload the page: it is still there. A refused change reverts the row the grid had already moved.

These three act on the table below, and this page implements all three itself. They are DOM work, which is why the package puts them in the React adapter rather than in the core; what the core supplies is the arithmetic, the row identity and the query. Click a name in the Name column to edit it: Enter saves to the server, Escape cancels. Right-click any row for its menu. Virtual renders only the rows on screen and replaces the page controls with a scrollbar; ticking it raises the page size to 200, because a page under a scrollbar is a data window rather than something anyone turns. Set the source to the ten million rows to see it do the work it is for.
