# Translation

The grid renders seventeen strings. All of them come from a message catalog, and none of them is
written into JSX, because a string literal in a component cannot be translated.

## The quick version

```tsx
import { Gridwright } from 'apsw-gridwright/react';
import { pl } from 'apsw-gridwright/locales';

<Gridwright columns={columns} data={people} locale={pl} />
```

That switches the text, the plural rules, the number formatting and the text direction together.

Bundled packs: `en`, `de`, `es`, `fr`, `pl`. They live behind their own entry point, so a bundler
drops the ones you do not import.

## The format

Keys are flat and dot-separated. Placeholders are ICU-style `{name}`. Plurals use the CLDR
categories that `Intl.PluralRules` returns.

None of that is invented here. It is what i18next, FormatJS, Lingui, Weblate and Crowdin already
consume, so a catalog is a file your translators can already open.

```ts
import type { LocaleCatalog } from 'apsw-gridwright';

export const it: LocaleCatalog = {
    locale: 'it',
    messages: {
        'search.placeholder': 'Cerca',
        'search.label': 'Cerca nelle righe',
        'status.loading': 'Caricamento delle righe',
        'status.empty': 'Nessuna riga da mostrare',
        'error.title': 'Impossibile caricare le righe',
        'error.retry': 'Riprova',
        'error.stale': 'Impossibile aggiornare le righe',
        'error.staleDetail': 'Vengono mostrati gli ultimi dati caricati',
        'selection.row': 'Seleziona la riga',
        'selection.all': 'Seleziona tutte le righe di questa pagina',
        'selection.count': {
            zero: 'Nessuna riga selezionata',
            one: '{count} riga selezionata',
            other: '{count} righe selezionate',
        },
        'sort.ascending': 'Ordina in modo crescente',
        'sort.descending': 'Ordina in modo decrescente',
        'sort.clear': 'Rimuovi ordinamento',
        'pagination.previous': 'Pagina precedente',
        'pagination.next': 'Pagina successiva',
        'pagination.rowsPerPage': 'Righe per pagina',
        'pagination.range': '{from}-{to} di {total}',
        'pagination.rangeUnknown': '{from}-{to} di molte',
        'a11y.sortedAscending': '{column}, ordinamento crescente',
        'a11y.sortedDescending': '{column}, ordinamento decrescente',
        'a11y.sortCleared': '{column}, non ordinato',
        'a11y.rowsShown': 'Da {from} a {to} di {total}',
        'a11y.rowsShownUnknown': 'Da {from} a {to} di molte',
        'a11y.rowsTotal': {
            one: '{count} riga',
            other: '{count} righe',
        },
        'tree.expand': 'Espandi',
        'tree.collapse': 'Comprimi',
        'tree.loadFailed': 'Impossibile caricare le righe figlie',
        'tree.cycle': 'Già mostrato più in alto',
        'tree.childCount': {
            one: '{count} elemento all'interno',
            other: '{count} elementi all'interno',
        },
    },
};
```

### The keys

| Key | Placeholders | Where it appears |
| :--- | :--- | :--- |
| `search.placeholder` | | the search box |
| `search.label` | | its accessible name |
| `status.loading` | | inside the table, and the live region |
| `status.empty` | | inside the table |
| `error.title` | | the error state |
| `error.retry` | | the retry button, shown only when retrying could help |
| `error.stale` / `error.staleDetail` | | the banner shown when a refresh failed and the previous rows are still on screen |
| `selection.row` | | each row checkbox |
| `selection.all` | | the header checkbox |
| `selection.count` | `{count}` | the toolbar; **plural** |
| `sort.ascending` / `sort.descending` / `sort.clear` | | the sort control's title, naming the next action |
| `pagination.previous` / `pagination.next` | | the page buttons |
| `pagination.rowsPerPage` | | the page size label |
| `pagination.range` | `{from}` `{to}` `{total}` | the row range |
| `pagination.rangeUnknown` | `{from}` `{to}` | the range when the source sent no total |
| `a11y.sortedAscending` / `a11y.sortedDescending` / `a11y.sortCleared` | `{column}` | the live region, after a sort control is activated |
| `a11y.rowsShown` | `{from}` `{to}` `{total}` | the live region, when a paginated result settles |
| `a11y.rowsShownUnknown` | `{from}` `{to}` | the same, when the source sent no total |
| `a11y.rowsTotal` | `{count}` | the live region for a virtualized grid; **plural** |
| `tree.expand` / `tree.collapse` | | the accessible name of a tree row's toggle |
| `tree.loadFailed` | | a node whose children would not load |
| `tree.cycle` | | a placement repeating a row already on its own path |
| `tree.childCount` | `{count}` | announced for an expanded node; **plural** |

The `a11y.*` keys are never drawn on screen. They are read out by assistive technology through the
grid's live region, which is exactly why they belong in the catalogue: a string nobody can see is
the easiest one to leave in English. See [Accessibility](accessibility.md) for when each is said.

Adding a key is a minor version. Renaming or removing one is a major, because every translator's
catalog is keyed on these.

## Plurals

This is why the catalog exists rather than a template string.

```ts
'selection.count': {
    zero: 'Nie zaznaczono wierszy',
    one: 'zaznaczono {count} wiersz',
    few: 'zaznaczono {count} wiersze',      // 2-4, 22-24, ...
    many: 'zaznaczono {count} wierszy',     // 5-21, 25-31, ...
    other: 'zaznaczono {count} wiersza',    // fractions
}
```

Polish needs four forms and Arabic six. English needs one, which is exactly why an English-speaking
author reaches for `${count} selected` and ships something no Slavic language can translate.

`Intl.PluralRules` picks the category, so this package carries no plural tables and no CLDR data.
Only `other` is required; a missing category falls back to it.

`zero` is an exact match on the number zero rather than a category, following ICU where an exact
match beats a keyword. English has no `zero` category at all, yet often wants a distinct sentence
for an empty selection.

## Numbers

A numeric placeholder is formatted with `Intl.NumberFormat` for the resolved locale, so a total of
12345 renders as `12,345` in English and `12.345` in German without the catalog saying anything.

Column values are yours to format, through `formatValue`:

```ts
{ id: 'salary', formatValue: (value) => new Intl.NumberFormat(locale, {
    style: 'currency', currency: 'EUR',
}).format(value) }
```

That is also what global search matches against, so a reader searching for what they can see finds
it.

## Word order

`pagination.range` is one message with three placeholders, not a label plus a separator plus a
count. A sentence assembled from fragments cannot be translated correctly, because languages do not
agree on where the numbers go relative to the words. Keep any message you add whole for the same
reason.

## Four ways in

Resolution order, highest first:

```
labels  →  translate  →  messages  →  locale catalog  →  English
```

### 1. A catalog

```tsx
<Gridwright locale={pl} />
```

The normal case.

### 2. A bare tag

```tsx
<Gridwright locale="de-DE" />
```

Sets plural rules, number formatting and direction while the text stays English. That is right for
`en-GB` and wrong for `pl`, which is why the catalog is a separate thing to pass.

### 3. Individual overrides

```tsx
<Gridwright locale={pl} messages={{ 'status.empty': 'Nie znaleziono pracowników' }} />
```

Applied over the catalog. Use it for wording specific to one screen.

### 4. An existing i18n library

```tsx
import { useTranslation } from 'react-i18next';

function People() {
    const { t } = useTranslation('grid');
    return <Gridwright columns={columns} data={people} translate={t} />;
}
```

`react-i18next`, `FormatJS` and `Lingui` all expose a function of the shape
`(key, values) => string`, so this is one prop rather than an adapter package. Put the keys in your
own resource files under whichever namespace you like.

Every major library returns the key itself when it has no entry for it. That is treated as "not
translated" and falls through to the catalog, so a missing key never renders as
`pagination.rowsPerPage` on screen.

### And `labels`

```tsx
<Gridwright locale={pl} labels={{ rowsPerPage: 'Na stronie' }} />
```

The escape hatch above all of it: direct label values, including the two that are functions. Use it
to change one string without shipping a catalog, or where a label needs logic a message cannot
express. The catalog is the translation path; this is not.

## Fallback

A key missing from a catalog resolves to English, never to the key. One English word in a
translated page is a cosmetic defect; `pagination.rowsPerPage` rendered in the footer is a broken
product.

Catch the drift in a test instead:

```ts
import { auditCatalog } from 'apsw-gridwright';
import { it as italian } from './locales/it';

test('the Italian catalog is complete', () => {
    const audit = auditCatalog(italian.messages);
    expect(audit.missing).toEqual([]);   // keys the catalog has not translated
    expect(audit.unknown).toEqual([]);   // keys that are no longer in the contract
});
```

## Right to left

Direction is resolved from the locale, through `Intl.Locale` where the runtime supports it and a
language list otherwise. The grid root then carries `dir="rtl"` and `lang`, and the stylesheet uses
logical properties (`margin-inline-end`, `border-inline`) so the layout mirrors rather than needing
a second stylesheet.

`dir` is set only for right-to-left, so a grid inside an already-RTL page does not reset itself to
the document direction it is nested in.

Override it if a catalog needs to disagree with its tag:

```ts
export const custom: LocaleCatalog = { locale: 'en', direction: 'rtl', messages };
```

No RTL catalog ships yet. The mechanism is tested; the translations are not written. A pull request
adding one is welcome.

## Outside React

The translator is part of the headless core and has no React dependency:

```ts
import { createTranslator } from 'apsw-gridwright';
import { pl } from 'apsw-gridwright/locales';

const translator = createTranslator({ catalog: pl });

translator.t('selection.count', { count: 3 });   // 'zaznaczono 3 wiersze'
translator.direction;                             // 'ltr'
translator.formatNumber(12345);                   // '12 345'
```

Inside React, `useGridwrightContext().translator` is the same object the grid is rendering
through, so a part you wrote yourself translates from the same catalog.

## Adding a locale to this package

1. `src/locales/<tag>.ts`, following an existing pack.
2. Export it from `src/locales/index.ts`.
3. Add the tag to the parameterised completeness test in `tests/unit/i18n.test.ts`.
4. Add it to the list in `scripts/check-exports.mjs`.
5. `npm run verify`.

Plural categories are the part worth care. Check which ones your language actually uses before
writing the forms:

```js
new Intl.PluralRules('pl').resolvedOptions().pluralCategories
// [ 'one', 'few', 'many', 'other' ]
```
